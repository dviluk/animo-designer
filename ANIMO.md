# animo-designer: what this fork changes, and how its server image is built

`dviluk/animo-designer` mirrors `open-pencil/open-pencil` for one self-hosted Cloud server on one of our own machines.
It carries six small changes of its own: four behind a build setting whose absence keeps upstream's behaviour, and
two fixes, the fifth and the sixth, which have none.
Everything else of ours lives outside this repository: the server's compose and settings files, its data folders and its
secrets.

## The first change: the editor need not ask the official server on start

- **What upstream does:** every start of the editor calls `checkCloudAvailability()` (`src/app/cloud/sessions/startup.ts`).
  That asks the hosted server, `OFFICIAL_CLOUD_URL` (`https://cloud.openpencil.dev` by default), whether it lists itself
  for this editor version. It carries no document, account or id, but it is a request to a third party from the
  browser of whoever opens our server.
- **Why we change it:** our server keeps nothing on a third party's servers (GitHub excepted), and its telemetry is
  off. This is the one call to the official server the editor makes unasked.
- **The setting:** `VITE_OPENPENCIL_OFFICIAL_CLOUD_CHECK=off`, read at build time like `VITE_OPENPENCIL_CLOUD`.
  - Without it, the editor behaves exactly as upstream's.
  - With it off, `checkCloudAvailability()` still reads the `?cloud=` switch but never asks the official server.
  - The connect dialog still checks the official server when a person chooses it there.
- **The tour, since upstream's `v0.17.0-beta.6`:** upstream dropped the bundled demo, and the editor fetches the tour
  from the official server's gallery (`fetchOfficialTour()`, `src/app/cloud/community/tour.ts`). With the check off,
  the tour is never fetched: `fetchOfficialTour()` answers null without asking, Help's "Open the Tour" is hidden by the
  menu feature `tour`, and the AI setup's welcome offers no tour. A visit to `/demo` says the tour is unavailable, as
  upstream's build without Cloud does.
- **The files:**
  - `vite.config.ts`: the define `__OPENPENCIL_OFFICIAL_CLOUD_CHECK__`;
  - `src/env.d.ts`: its declaration;
  - `src/constants.ts`: `OFFICIAL_CLOUD_CHECK`, true when the define is missing;
  - `src/app/cloud/availability.ts`: the early return;
  - `src/app/cloud/community/tour.ts`: the tour's early return;
  - `src/app/shell/menu/features.ts`, `src/app/shell/menu/schema/types.ts` and `src/app/shell/menu/schema/help.ts`:
    the menu feature `tour`, with `desktop/generated/menu.json` regenerated by `bun run generate:tauri-menu`;
  - `src/app/ai/models/settings/onboarding/dialog.ts`: the welcome's tour offer;
  - `tests/app/demo/tour-official-check.test.ts`.

## The second change: online fonts may start off

- **What upstream does:** online fonts are on by default. Every start lists the font families at `api.fontsource.org`,
  and a document using a font other than the bundled Inter, or holding Chinese, Japanese, Korean or Arabic text, loads
  its faces from `cdn.jsdelivr.net`.
- **The setting:** `VITE_OPENPENCIL_ONLINE_FONTS=off`, read at build time.
  - Without it, online fonts are on by default, as upstream's.
  - With it off, `DEFAULT_ONLINE_FONTS` is false: no font provider is enabled, so the editor lists no font from
    outside and fetches none for a document's text. Settings can still turn online fonts on, and its reset goes back
    to off.
  - One exception, since upstream's `v0.17.0-beta.6`: HTML brought in loads the fonts its own `@font-face` rules name,
    from wherever they name them, whatever this setting says (What still reaches outside).
- **The files:** `vite.config.ts` (the define `__OPENPENCIL_ONLINE_FONTS__`), `src/env.d.ts`, and
  `src/app/editor/fonts/index.ts` (`DEFAULT_ONLINE_FONTS`).

## The third change: icons from a local set

- **What upstream does:** icons come from the Iconify API (`https://api.iconify.design`), and Material Symbols are
  drawn from Google's fonts. Searching, browsing and placing an icon each fetch from outside, in the editor and in the
  command-line tool.
- **The settings:** `VITE_OPENPENCIL_LOCAL_ICONS=lucide` for the editor, read at build time, and
  `OPENPENCIL_LOCAL_ICONS=lucide` for the command-line tool, read when it runs.
  - Without them, icons are upstream's.
  - With them, every icon the editor and the command-line tool search, browse and draw comes from the Lucide set
    bundled as `@iconify-json/lucide`, and none is fetched. Any other set is refused by name.
  - One exception: the command-line tool's `import` (below) still names icons with upstream's matcher.
- **Naming imported icons, since upstream's `v0.17.0-beta.6`:** upstream names the SVG icons in HTML brought in by
  import, paste or Place by how they draw (the Settings switch `import.nameIcons`, on by default), with whaticon's
  index downloaded from `https://cdn.jsdelivr.net/npm/whaticon@0.4.0/data`. With local icons, `importIconMatcher()`
  gives no matcher, so nothing is downloaded and every SVG comes in as drawn, unnamed. The Settings switch then changes
  nothing: only the bundled Lucide set could match.
  - This covers the editor only. The command-line tool's `import` builds upstream's matcher whenever `--icon-names` is
    on, its default (`packages/cli/src/commands/import.ts`), whatever `OPENPENCIL_LOCAL_ICONS` says: it downloads the
    same index and draws upstream's icons. `--no-icon-names` turns it off. Our `openpencil.sh` runs the tool with no
    network, so there the import warns and brings every SVG in unnamed.
- **The files:**
  - `packages/core/src/icons/local.ts`: a client with the Iconify client's calls, answered from sets in memory, under
    upstream's `createIconifyProvider`; `loadLucideIconSet()` loads the set on first use;
  - `vite.config.ts`, `src/env.d.ts` and `src/constants.ts`: the define `__OPENPENCIL_LOCAL_ICONS__` and `LOCAL_ICONS`;
  - `src/app/editor/icons/provider.ts`: `appIcons` and `importIconMatcher()`; `packages/cli/src/tool-data.ts`: the
    command-line tool's icons;
  - `tests/app/editor/icons/import-matcher.test.ts`.

## The fourth change: the agents' editor

- **What upstream does:** a Cloud site's editor, built or served, has no agent link; only the desktop app and a
  development server pair the editor with the agent (MCP) server.
- **The setting:** `VITE_OPENPENCIL_AGENT_EDITOR=on`, read at build time, for a second build that only the agents'
  own browser loads. The editor a person loads is never built with it.
  - A development server with it is automated as the desktop's is.
  - A built editor with it fetches its agent server's token from `/__agents/token` on its own origin, then connects to
    the agent server at `127.0.0.1:7600`. Anything but a 64-hex token there leaves it without agents. No token is in
    the bundle.
  - The server that serves this build, and the agent server beside it, live outside this repository.
- **The files:** `vite.config.ts`, `src/env.d.ts` and `src/constants.ts` (`__OPENPENCIL_AGENT_EDITOR__`,
  `AGENT_EDITOR`); `src/app/automation/mcp/runtime.ts` (`localMCPAvailable`) and `spawn.ts`
  (`readAgentEditorHandle`).

## The fifth change: a minimum or maximum size bound to a variable is kept

- **What upstream does:** design JSX resolves a FLOAT variable only in the props `scalarProps()` lists
  (`packages/design-jsx/src/variables/props.ts`), and `minW`, `maxW`, `minH` and `maxH` aren't there. So
  `minH={designVar(…)}` reaches `sizeLimit()` (`packages/design-jsx/src/overrides/state.ts`) as the variable itself,
  which keeps numbers only, and the size limit is dropped with no warning. The scene graph binds all four fields.
- **Why we change it:** the Fieldbook's parts give every touch target its 48 px floor as a variable, so a button drew
  24 px high.
- **The setting:** none; this is a fix. If upstream fixes it, take theirs and drop this change.
- **The files:** `packages/design-jsx/src/variables/props.ts` (the four props), `packages/design-jsx/src/tree.ts`
  (their types), `packages/design-jsx/src/reference/authoring.md` (the props a FLOAT reference works in) and its two
  generated copies, `packages/docs/reference/design-authoring.md` and
  `skills/open-pencil/references/design-authoring.md`, and `packages/core/tests/design-jsx/scalar-variables.test.ts`.
  On a merge conflict in the reference, resolve the source and run `bun run generate:authoring-reference`; never
  hand-merge the copies.

## The sixth change: a detach, a type change, a move or a delete inside a component no longer breaks later pages, and a detach's save keeps the layer and what instances read before it changed inside it

- **What upstream does:**
  - **Detach turns the layer into a frame in place without telling the graph** (`detachInstance`,
    `packages/scene-graph/src/instances/index.ts`). So nothing sees the edit: a reader worker goes on loading from the
    opened file, and the room hears of the detach only with the layer's next change.
  - **A later page load builds each new instance of the component from the file's copy,** where the layer is still an
    instance. It then refuses the link to the live frame (`Invalid source child`,
    `packages/fig/src/instance-overrides/materialize-instance.ts`).
  - **A save loads the pages not yet shown the same way,** so it fails too. Every later page holding an instance of
    that component, and every save, fails until the design is reopened, in one window as in two.
  - **"Convert to frame" or "to group" on a layer inside a component** breaks later pages and saves the same way: the
    file's copy and the live layer differ in type.
  - **A delete inside a component breaks them too, when an instance on a page not yet shown changed something on the
    deleted layer or inside it,** such as a hidden icon. The page load leaves the deleted layer's copy out, then still
    looks for it to record the instance's change, and fails with `Expected one instance-path target … found 0`
    (`recordPropertyClaims`, `packages/fig/src/instance-overrides/materialize-instance.ts`).
  - **A layer moved to another parent inside a component breaks them the same way,** when an instance on a page not
    yet shown changed something on that layer or inside it. The page load leaves its copy out where the file had it,
    then still looks for it.
  - **A detach on a page is dropped from the save,** with any change made to that layer after it, since the save sees
    no change. The reopened design holds the instance as it was.
  - **An instance the detached layer held takes the detached instance's record of which layer each of its layers
    copies** (`adoptNestedOverrides`, `packages/scene-graph/src/instances/index.ts`). That record names layers of the
    detached instance's component, which a copy of the held instance doesn't bring, so Copy of it, of the detached
    layer or of anything holding them fails with `Missing instance geometry address`.
- **Why we change it:** a detach, a type change, a move or a delete inside a component is an ordinary edit. After one, a window
  could neither show those pages nor save, and a detach on a page was quietly lost.
- **What it does:**
  - **Detach writes through `graph.updateNode`,** as its undo already did. Observers see the edit, the room gets it at
    once, and the instance index drops the instance.
  - **An instance the detached layer held keeps its own record of which layer each of its layers copies,** in its own
    component. What the detached instance changed on those layers still moves to it.
  - **A page load into an edited drawing leaves the stale copy out of a new instance.** That is the copy of a layer
    whose type in the component is no longer the type the file gives the copy, whatever changed it: a detach, "Convert
    to frame" or "to group", or "Create component". It is left out as the copy of a deleted layer is, and the
    instance's sync after its build copies the layer in as it is now. The copy of a layer moved to another parent is
    left out where it was, the same way, and copied in where the layer is now.
  - **The load then drops what the instance changed on a copy it left out,** the copy itself or anything inside it,
    where it used to fail. Only a copy this load left out is skipped this way: a change whose layer is missing for any
    other reason still fails the load. Each load keeps one record of the copies it left out
    (`packages/fig/src/document/materialize.ts`), which `reachesLeftOutCopy` reads
    (`packages/fig/src/instance-overrides/occurrence/path.ts`).
  - **A save writes a detached layer whole.** The layer's own record changes to a frame. The layers inside it were
    the instance's copies, which the file holds only as that instance's overrides, so the save writes each of them as a
    record of its own. It stops at an instance or a generated frame, which writes what it holds on its own record. A
    save with no edit still returns the opened file unchanged. A detach on a page changes only that layer and the
    layers inside it. A change inside a component also syncs that component's instances already read, with the size
    reset below.
  - **A save writes what an instance read before the detach changed inside the detached layer against that layer's
    own layers.** The window keeps such an instance as it was built, its copy of the layer still an instance, whose
    layers copy the old component's. The save's path to each change used to name those, which the saved file no
    longer holds. It now names the detached layer's own layer that copies the one named (`instanceExportAddress`,
    `staleCopyNames`, `packages/fig/src/node-change/instance/geometry.ts`):
    - **The detach keeps a link for each layer it frees,** down to each instance it held: in the detached layer's own
      overrides, keyed by the freed layer's id, the layer of the component that layer copies (`copiedLayerLinks`,
      `packages/scene-graph/src/instances/index.ts`). They are all it keeps of its overrides. A save writes no frame's
      overrides, so a reopen drops them, and no copy built before the detach is then left to need them.
    - **The save follows only those links,** never `componentId`, which Duplicate copies onto the new layer. A layer
      put into the detached layer after the detach, by Duplicate or by a paste, has a new id and so no link: the
      original keeps the change, wherever the copy sits. A layer moved in from another detached layer keeps its link
      in that one, so it has none here either. Two layers linked to one source give it none.
    - **The save never sends a path onto a layer that another layer of the same copy names itself,** as a layer the
      window added to that copy after the detach does: two layers with one address make the save fail (`Ambiguous
      instance geometry address`). Such a change keeps its old path. A save maps each such copy once for an
      instance's claims and once for its geometry.

    The reopened instance keeps those changes, in one window as in two. The save adds no override key: two detached
    copies of one component inside one component would carry the same keys, and a change saved after a reopen then
    makes that save fail with the same error.
- **The limits:**
  - **An instance on a page not yet shown keeps nothing it changed on that layer's copy or inside it,** after a
    detach as after the other changes, such as the dot's colour in that one instance.
    - When: on that page's first load after the change, or on a save.
    - The copy becomes the component's layer as it is now. The page shows, and the save goes through.
    - Keeping the instance's own change waits for a later change to how a page load builds instances.
  - **An instance read before a detach loses what it changed on a layer then deleted from the detached layer or moved
    out of it.** The save writes that change's path as before the detach, and the reopened design skips a path that
    finds no layer, with no notice. The window may show the change until a reopen. A deleted layer takes its changes
    with it, as anywhere, and a moved one shows as the component has it.
  - **"Create component" on a layer detached inside a component loses, at the save, what an instance read before the
    detach changed inside that layer.** The window still shows it, and the hide on the layer itself stays. The code
    before this fix loses it too. A person reopens the design after making such a layer a component, and sets those
    changes again.
  - **Upstream's sync resets the inner sizes of the instances already read.** Whenever a layer inside a component
    changes, a plain rename included, the sync puts the component's sizes over the sizes Figma derived for those
    instances' inner layers, in the window and in the save: a progress bar's fill takes the component's width. A
    detach or a type change inside a component now reaches that sync, where upstream failed first. A person checks
    those instances' sizes after such a change, and sets again what was reset.
  - **A copy built before the change keeps the type it was built with in that window,** and so does a copy two levels
    down, inside an instance another component holds, even on a page loaded after the change. After an undo of a
    detach, a copy built while the layer was detached keeps the frame's type the same way. The saved file holds each
    such copy as the component has it. A person reopens the design to see it as saved.
  - **After an undo of a detach, the instance stays out of the instance index.** This one is upstream's: the index
    checks the type before the undo writes INSTANCE back (`packages/scene-graph/src/graph.ts`). Later edits to its
    component don't reach it in that window, and the save skips it when it writes the component's instances. A person
    reopens the design after undoing a detach, before editing that component.
- **The setting:** none; this is a fix. If upstream fixes it, take theirs and drop this change.
- **The files:**
  - `packages/scene-graph/src/instances/index.ts` (`detachInstance`, `copiedLayerLinks`, `adoptNestedOverrides`);
  - `packages/fig/src/instance-overrides/source-children.ts` (`reconcileOccurrenceStructure`, `changedTypeSince`);
  - `packages/fig/src/instance-overrides/occurrence/path.ts` (`reachesLeftOutCopy`);
  - `packages/fig/src/instance-overrides/materialize-instance.ts` (`claimTarget`);
  - `packages/fig/src/document/materialize.ts` (the load's record of the copies it left out);
  - `packages/fig/src/node-change/convert.ts` (`resolveNodeType`, now exported);
  - `packages/core/src/io/formats/fig/export/patch/index.ts` (`planRecords`, `addUnrecordedDescendants`);
  - `packages/fig/src/node-change/instance/geometry.ts` (`instanceExportAddress`, `staleCopyNames`, `keptLinks`);
  - `packages/fig/src/node-change/export/override-claims.ts` (`serializeRuntimePropertyOverrides`, one map of the
    copies built before a detach for an instance's claims);
  - `tests/integration/collab/cloud/component-detach.test.ts`, `component-detach-overrides.test.ts`,
    `component-detach-pairs.test.ts` and `component-detach-copy.test.ts`, and their helper,
    `tests/helpers/collab/component-tabs.ts`;
  - `packages/fig/tests/instance-overrides/materialize.test.ts`;
  - `packages/core/tests/editor/components/detach.test.ts`.

## The seventh change: the agent server keeps up to 32 sessions

- **What upstream does:** the agent (MCP) server refuses a new session once 10 are open ("Too many active MCP
  sessions"). A session ends when its client closes it, or after 15 minutes idle.
- **Why we change it:** the agents' editor serves several agents at once, and a client that stops without closing its
  session keeps its place until that idle time ends. Ten filled up in ordinary use, and the next agent was refused.
- **What it does:** the limit is 32. The idle time stays at 15 minutes.
- **The setting:** none; the limit is a constant.
- **The files:** `packages/mcp/src/server/sessions.ts` (`MAX_MCP_SESSIONS`), the three tests that pin the limit,
  `packages/mcp/tests/server/security.test.ts`, `sessions.test.ts` and `transport.test.ts`, and
  `packages/mcp/README.md`.

## What still reaches outside

With the first three settings set, the served editor still makes these requests:

- **When a message is opened in a browser:** the server's e-mails show their logo from `openpencil.dev`
  (`packages/cloud/src/email/templates/brand.ts`). We accept it: our mails are read through the mail catcher's API, which
  loads no image.
- **Only when a person chooses them:**
  - online fonts turned on in Settings, AI, stock photos, web search, and live rooms for files on the device;
  - the official server, in the connect dialog or from a link that names it;
  - since upstream's `v0.17.0-beta.6`, HTML brought in by import, Open from URL, Place or paste: the browser loads the
    page's linked stylesheets, its pictures and its `@font-face` fonts from wherever the page names them
    (`src/app/document/io/dom.ts`, `src/app/editor/clipboard/paste/web.ts`). A copied layout with no text pastes
    straight to layers, with no "Paste as layers" choice first.
- **On every page load:** the editor probes `http://127.0.0.1:7600/health` for a desktop agent server. It stays on the
  machine that runs the browser.
- **In the command-line tool:** a `.pen` file's own icons are still read through upstream's icons, and `import` names
  icons online unless `--no-icon-names` is given (the third change).

These reach outside only when switched on, and none is on for us:

- **On the server, each by a section of its settings file, which ours doesn't have:** billing (`[billing]`), sign-in
  through Google, Apple or GitHub (`[authentication.providers]`), and server errors sent to PostHog
  (`[error_tracking]`).
- **In the build:** the usage ping, and the campaigns its answer brings, only with `VITE_OPENPENCIL_FEEDBACK=on`
  (below).

## Comments live on the server

Since upstream's `v0.17.0-beta.6`, a Cloud document's comments live in the server's database, not in its stored
file.

- **A save to the server leaves them out of the file** (`src/app/document/io/source/actions.ts`), and the editor shows
  the server's threads in place of any the file holds (`src/app/cloud/comments/sync.ts`).
- **A file's own comments come in only once,** when a document this device made is first uploaded. A document already
  on the server keeps its old comments only in its earlier versions.
- **What follows from it:**
  - A file downloaded through the server's API carries none of the server's comments. The editor's Save As and the
    portal's download write them back into theirs (`src/app/cloud/comments/file.ts`).
  - A backup must hold the database, since the stored files no longer hold the comments.

## Building the server image

The image is upstream's `packages/cloud/deploy/Dockerfile`, unchanged. Two steps, from the repository's root:

1. **The HTML engine's WebAssembly module.** The image has no Rust, so the module is built first and travels in the
   build context: `bun run --filter @open-pencil/html-engine build:wasm` (Rust from `rust-toolchain.toml`, target
   `wasm32-unknown-unknown`).
2. **The image,** with the three settings in a git-ignored `.env.cloud.local` at the root, which
   `vite build --mode cloud` reads. The build context leaves out no `.env*` file:

   ```bash
   printf 'VITE_OPENPENCIL_OFFICIAL_CLOUD_CHECK=off\nVITE_OPENPENCIL_ONLINE_FONTS=off\nVITE_OPENPENCIL_LOCAL_ICONS=lucide\n' > .env.cloud.local
   docker build -f packages/cloud/deploy/Dockerfile -t animo-designer-cloud:<version>-<sha> .
   ```

The agents' editor is a second `vite build --mode cloud` with `VITE_OPENPENCIL_AGENT_EDITOR=on` added, served by its
own container; it never goes into the server's image.

Never set `VITE_OPENPENCIL_FEEDBACK`: without it the editor sends no usage events and no ping, so it receives no
campaigns.

## Keeping up with upstream

- Merge upstream's newest release tag in, never `upstream/master` between releases, and never rebase.
- Keep each change small and behind its setting, or, for a fix, say in its section when to drop it, so a merge stays
  easy.
- If upstream gains a setting of its own for the same thing, drop that change and use theirs.
